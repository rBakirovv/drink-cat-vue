# Конституция drink-cat-vue

`README.md` объясняет, что есть в проекте и как его запустить. Здесь — правила разработки для людей и агентов.

**Перед реализацией любой новой фичи, изменением поведения или исправлением бага применяем [навык TDD](.agents/skills/tdd/SKILL.md). Начинаем с падающего теста и только после этого меняем код приложения.**

## Стек и конфигурация

Vue 3, TypeScript, Vite, Vue Router, Pinia, shadcn-vue, Tailwind CSS и `@lucide/vue`.
Правила кода и импортов живут в `eslint.config.ts` и `.oxlintrc.json`, форматирование — в `.oxfmtrc.json`. Перед изменением поведения инструмента проверь его существующий конфиг.

## Архитектура FSD

- Новый код размещаем в `src/` по слоям: `app` → `pages` → `widgets` → `features` → `entities` → `shared`. Стрелка показывает разрешённое направление зависимостей; можно пропускать слои. Слайсы одного слоя друг друга не импортируют.
- `app` собирает приложение и роутер, `pages` — экраны, `widgets` — крупные блоки, `features` — действия пользователя, `entities` — предметные сущности, `shared` — общий код без привязки к предметной области. В `app` и `shared` используем сегменты без слайсов.
- Снаружи слайса импортируем через его `index.ts` и алиас `@/`, например `@/entities/drink`. Внутри слайса используем относительные импорты. Границы и порядок импортов проверяет ESLint; порядок — предупреждение.
- В слайсе `ui/` содержит компоненты, `model/` — состояние и логику, `api/` — запросы, `lib/` — вспомогательные функции. Заводим слой или сегмент, когда появляется код для него. Стартовую структуру Vue переносим по мере замены шаблона.
- Если назначение слайса или его публичный API требуют пояснения, добавляем рядом короткий `README.md`: зачем нужен слайс, что экспортирует и какие решения важно знать.

## Компоненты и интерфейс

- Один `.vue` файл — один компонент. Для новых компонентов используем `<script setup lang="ts">` и понятные имена в `PascalCase`. Компоненты из реестра shadcn-vue сохраняют исходные имена, например `Button`.
- Разметку и простое локальное состояние держим в компоненте. Сложную или переиспользуемую логику выносим в `model/` (например, в `useDrinkForm.ts`), запросы — в `api/`. Pinia используем для состояния, которым должны делиться разные части приложения.
- Кнопки, поля и диалоги берём из shadcn-vue: исходники храним в `src/shared/ui/`, добавляем через CLI. Утилиты компонентов находятся в `src/shared/lib/`; иконки импортируем по имени из `@lucide/vue`. Свой примитив добавляем, если готовый компонент не покрывает задачу.
- Для раскладки, отступов и адаптивности используем классы Tailwind CSS. Глобальный сброс Preflight включён для корректной работы стилей shadcn-vue. Тема настроена в `src/assets/main.css` и следует системной цветовой схеме.

## Тесты, проверки и Git

- В каждом цикле формулируем один наблюдаемый результат, пишем тест через пользовательский интерфейс или публичный API и запускаем его. Убеждаемся, что тест падает по ожидаемой причине, затем вносим минимальное изменение и проверяем, что тест проходит.
- Для исправления бага падающий тест должен воспроизводить проблему. Для новой фичи или изменения поведения он должен фиксировать ожидаемый результат.
- Модульные и компонентные тесты пишем на Vitest и Vue Test Utils, рядом с кодом. Playwright в `e2e/` используем для ключевых сценариев через интерфейс. Для сложной правки интерфейса также проверяем затронутые состояния в браузере.
- Перед завершением изменений в коде запускаем проверки из README по масштабу задачи: линтер, проверку формата, тесты и сборку. Изменение только документации проверяем по ссылкам и командам.
- После завершения фичи и прохождения проверок предлагаем пользователю сделать коммит и приводим текст сообщения.
- Сообщения коммитов пишем на русском, сохраняя префиксы, например `feat: добавить каталог напитков` или `fix: исправить сохранение формы`. Коммит и отправку выполняем по запросу.

## Навыки агентов

Навыки из `vacation` хранятся в `.agents/skills/`. Для Claude Code в `.claude/skills/` есть ссылки на те же файлы. Источники и хеши записаны в `skills-lock.json`.

- [`tdd`](.agents/skills/tdd/SKILL.md) — обязательный порядок разработки для фич, изменений поведения и исправлений. Публичную границу для теста берём из требований задачи и уточняем, если от выбора зависит поведение.
- [`testing-best-practices`](.agents/skills/testing-best-practices/SKILL.md) — для выбора сценариев, написания и ревью тестов. Применяем общие принципы к Vitest, Vue Test Utils и Playwright; примеры для React не задают правила для Vue.
- [`grilling`](.agents/skills/grilling/SKILL.md) — когда пользователь просит разобрать план или проверить спорное решение вопросами. [`grill-me`](.agents/skills/grill-me/SKILL.md) — ручная команда запуска этого же навыка.
