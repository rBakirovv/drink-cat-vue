# drink-cat-vue

Drink Cat — веб-приложение кофейни на Vue 3 и TypeScript. Сейчас в нём можно посмотреть популярные напитки, открыть карточку напитка, выбрать объём, ввести номер телефона и настроить уведомления. Приложение можно установить как PWA.

Договорённости по архитектуре, тестам и Git — в [конституции проекта](CLAUDE.md).

## Контекст для бэкенда

Каталог и фотографии загружает `drink-cat-nest`. Вход и настройки уведомлений пока работают локально.

### Каталог и размеры

- Карусель на `/` получает список из `GET /api/drinks?popular=true`. Карточка по адресу `/drinks/:drinkId` загружает данные из `GET /api/drinks/:drinkId` и показывает «Напиток не найден», если API вернул `404`.
- `id` — строковый идентификатор для URL, `price` — число в целых рублях. Фото приходят по путям `/api/drink-images/…` из поля `image`. Service worker кэширует успешно загруженные ответы каталога и фото для повторного открытия офлайн. [Типы](src/entities/drink/model/types.ts), [запросы](src/entities/drink/api/drinks.ts).
- На странице напитка доступны S (250 мл), M (350 мл) и L (450 мл). По умолчанию выбран M. Размеры одинаковы для всех напитков, выбор размера не меняет цену. Кнопка добавления отключена. Корзина и оформление заказа пока отсутствуют. [Страница напитка](src/pages/drink-detail/ui/DrinkDetailPage.vue).

### Вход по телефону

Форма на главной форматирует номер как `+7 (XXX) XXX-XX-XX` и активирует кнопку «Получить код» после ввода полного номера. Отправка формы меняет локальное состояние. Отправка SMS, поле для ввода кода и пользовательская сессия пока отсутствуют. [Форма телефона](src/pages/home/ui/PhoneDrawer.vue).

### PWA и уведомления

На HTTPS-стенде с включённым тестовым Web Push переключатель в меню создаёт подписку по нажатию и передаёт её в NestJS. При выключении Vue удаляет подписку. При отключённом тестовом API переключатель управляет локальной настройкой. Service worker показывает текст полученного push с заголовком «Тестовое уведомление». Настройка стенда и запрос Postman описаны в разделе «Тестовый Web Push на iPhone» в README бэкенда. [Переключатель](src/pages/home/ui/CatMenu.vue), [обработчик push](public/push-handler.js).

### Следующие этапы интеграции

1. **Вход.** Добавить запрос кода и его подтверждение. Передавать номер в нормализованном виде `+7XXXXXXXXXX`. Согласовать срок действия кода, повторную отправку, лимиты попыток и способ выдачи сессии после подтверждения.
2. **Заказы.** Определить, что пользователь сможет добавить и как оформить заказ. Для варианта напитка согласовать идентификатор и цену, которую сервер проверяет при оформлении.
3. **Web Push.** Тестовая подписка уже работает. Для продакшена нужно согласовать хранение подписок и сценарии отправки.

## Запуск для разработки

Нужен Node.js 22.18+ в ветке 22.x или Node.js 24.12 и новее.

Запусти `npm ci` и `npm run start:dev` в соседнем репозитории `drink-cat-nest`. Затем запусти фронтенд:

```sh
npm ci
npm run dev
```

Vite проксирует `/api` на `http://127.0.0.1:3000`. Чтобы использовать другой адрес NestJS, задай переменную окружения `DRINK_CAT_API_TARGET` перед запуском Vite.

При размещении сборки проксируй `/api` на NestJS с того же домена. Прямые ссылки Vue, например `/drinks/cappuccino`, должны отдавать `index.html`.

Открой адрес, который выведет Vite (обычно `http://localhost:5173`). Для VS Code рекомендуются расширения из [настроек проекта](.vscode/extensions.json), в том числе Vue (Official) и Oxc.

Чтобы открыть приложение на телефоне, подключи телефон и компьютер к одной сети Wi-Fi и открой на телефоне адрес из строки `Network` в выводе Vite.

## Docker и GitLab CI

[Dockerfile](Dockerfile) собирает Vue и упаковывает `dist` в непривилегированный контейнер Nginx. [Nginx](nginx.conf) отдаёт статику и service worker, а `/api/*` проксирует в сервис `api:3000`. Общий `compose.prod.yml` для Vue и NestJS лежит в `drink-cat-nest`.

[GitLab CI](.gitlab-ci.yml) запускает проверки на раннере `docker-build` и публикует образ основной ветки в Container Registry с тегом полного коммита. Для проверки PWA поверх уже запущенных контейнеров используй:

```sh
CI=1 DRINK_CAT_E2E_URL=http://127.0.0.1:8080 npm run test:e2e -- --project=chromium
```

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Запускает сервер разработки |
| `npm run type-check` | Проверяет TypeScript, в том числе в `.vue` файлах |
| `npm run lint` | Запускает Oxlint и ESLint, исправляет то, что можно исправить автоматически |
| `npm run format` | Форматирует `src/` через Oxfmt |
| `npx oxfmt --check src/` | Проверяет форматирование без правок |
| `npm run test:unit -- --run` | Запускает тесты Vitest один раз |
| `npm run test:e2e -- --project=chromium` | Запускает сквозные тесты Playwright в Chromium |
| `npm run build` | Проверяет типы и собирает приложение в `dist/` |

Перед первым запуском сквозных тестов установи браузер командой `npx playwright install chromium`. Playwright запускает NestJS из соседнего `drink-cat-nest`, где уже установлены зависимости. Если задан `DRINK_CAT_API_TARGET`, Playwright использует уже запущенный сервер по этому адресу.

| Путь | Что в нём |

| `src/main.ts` | Точка входа: Vue, Pinia и роутер |

| `src/entities/drink/` | Типы, запросы каталога и компонент карточки |

Новый код размещаем по FSD внутри `src/`. Слои и правила импортов описаны в [конституции проекта](CLAUDE.md#архитектура-fsd).

## Компоненты интерфейса

Используем [shadcn-vue](https://www.shadcn-vue.com/docs/installation/vite): компоненты добавляются в исходники проекта. Например:

```sh
npx shadcn-vue@latest add input dialog
```

CLI настроен на `src/shared/ui/`. Кнопка уже доступна через `import { Button } from '@/shared/ui/button'`. Компоненты импортируем локально; глобальной регистрации нет. Тема и Tailwind Preflight подключены в `src/assets/main.css`, тёмная тема следует системным настройкам.
